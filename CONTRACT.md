# Implementation Contract

Independent local application; no production integration. Single FastAPI process serves built Vite app, REST and WebSocket. Python 3.12, Node 22.23.1. Camera pixels are processed browser/video data, never RAW. Firmware locks and brightness are not guaranteed. User-requested launcher default is 0.0.0.0 with auto LAN HTTPS and reusable private local CA; --local explicitly selects former loopback HTTP. Origin remains exact configured LAN URL, never wildcard.

## HTTP

All authenticated endpoints use `Authorization: Bearer <cameraToken>`; display token cannot call camera routes. Origin, when supplied, must match configured `COLORLAB_ORIGIN` (default http://localhost:8443 for development). Mutating browser endpoints and WebSocket require exact Origin; authenticated same-origin GET may omit Origin because browsers do so. JSON bodies finite numbers, bounded counts, strict models. Responses are camelCase.

- `POST /api/sessions` body `{mode: "threeStage"|"catalogOnly"|"replay", conditions: {...}}` -> `{sessionId,cameraToken,displayToken,expiresAt,state,profileVersion}`. Token expiry, one active device per role; QR uses `/display#session=<id>&token=<displayToken>`.
- `GET /api/sessions/{id}` -> session snapshot including state, profileVersion, capabilities, conditions, references, cameraProfile, displayProfile, measurements, currentPatch, paused, pauseReason.
- `PATCH /api/sessions/{id}/conditions` body `{conditions: {...}}` invalidates dependent profiles and downstream results when fingerprint changes. Display-only settings invalidate display/match, not retained catalog estimates; camera/target conditions invalidate downstream approval without deleting historical evidence.
- `POST /api/sessions/{id}/reference` body a ReferenceTarget, or `{exploratory: true}`. Target: `{id,label,source,version,valueType:"XYZ"|"Lab",referenceWhite:"D50"|"D65",observer:"2"|"10",xyzScale:1,validity:"verified"|"unverified",patches:[{id,values:[n,n,n],split:"train"|"holdout",neutral:boolean}],geometry:null,health:null}`.
- `POST /api/sessions/{id}/camera-profile` body `{observations:[{patchId,frames:[Frame]}],fingerprint:string}`. Exploratory may use empty observations, returns profile with `status:"exploratory"`; referenced fit requires disjoint physical training/holdout patches and accepted capture quality. Returns CameraProfile; moves to display stage (fabric for explicit catalogOnly/replay).
- `POST /api/sessions/{id}/captures/analyze` body `{frames:[Frame],region:Region}` -> robust summary plus quality; not a calibration. Region `{id,label,order,mode:"solid"|"bands"|"patterned",polygon:[[x,y],...],exclusions:[[[x,y],...]],background:null|str,layers:null|int,direction:null|str,operatorConfirmed:boolean}`.
- `POST /api/sessions/{id}/display-profile` body `{observations:[{drive:[0..1,0..1,0..1],frames:[Frame],witnessFrames:[Frame],cardPatchId:null|str,split:"train"|"holdout",commandSequence:int,patchId:str}],contaminationBaseline:[Frame],contaminationChecks:[[Frame]],layout:"single",fingerprint:string}`. Requires camera profile, physical witness observations and contamination test; returns display response model/profile or explicit rejection. Status CameraReferencedDisplayCompensationProfile, not ICC or absolute calibration.
- `POST /api/sessions/{id}/measurements` body `{region:Region,frames:[Frame],sourceColorSpace:string,sourceCaptureIds:[str],capturedAt:string}` -> Measurement, appended server-side. Invalid samples retained, approved export excludes their catalog color (never excludes the failure report). RGB output from display never affects catalog.
- `POST /api/sessions/{id}/matches` body `{measurementId:string,maxEvaluations:40,target:0.01,noiseFloor:0.002}` -> `{runId,nextDrive:[n,n,n],status,patchId,commandSequence}`. Match objective normalized linear camera RGB; DE00 optional surrogate only with referenced camera model.
- `POST /api/sessions/{id}/matches/{runId}/observe` body `{frames:[Frame],witnessFrames:[Frame],markerSequence:int,commandSequence:int,patchId:string,stable:boolean,layout:"single"|"group"}` -> `{runId,nextDrive:null|[n,n,n],status,terminationReason,bestDrive,objectiveValue,iterations}`. Requires fresh server command, render acknowledgement, marker sequence and stable physical witnesses, unique fresh frame identities. Server owns loop; never trusts final measurements supplied by clients.
- `POST /api/sessions/{id}/images` multipart file original encoded image, explicit retention field false default -> `{captureId,width,height,sourceColorSpace,colorProvenance,previewUrl}`. Raw ICC decode only in server; browser preview PNG is canonical sRGB and must not reapply original ICC. Unknown ICC rejected, missing ICC explicit assumed-sRGB exploratory. Used only for replay/approximate source; uploading full image is explicit consent.
- `POST /api/sessions/{id}/images/{captureId}/regions` `{regions:[Region]}` -> replay Measurements from original coordinates and masks, always exploratory without capture-linked reference. `POST .../suggest-bands` `{polygon,orientation:"horizontal"|"vertical"}` -> suggested Regions, operatorConfirmed false.
- `GET /api/sessions/{id}/export?format=json|csv&kind=experimental|approved` -> full report or CSV. Camera authenticated. JSON includes failed measurements and experimental/approved category. Approved catalog values only for valid, operator-confirmed referenced live captures. No invented instrument DE.
- `POST /api/sessions/{id}/measurements/{measurementId}/override` body `{catalogHexSrgb:"#RRGGBB",reason:string}` creates a new unapproved provenance-linked manual version. Never changes original measured XYZ/Lab or an existing display command.
- `POST /api/sessions/{id}/validations` accepts operator report type repeatability/reacquisition/instrument with provenance. Appends a report, does not rewrite historical measurements or attest physical evidence. Instrument comparison requires source measurement identity/version and compatible declared conditions.
- Explicit additional session mode `cameraMatch` is camera-domain-only experimental live display matching, not a shortcut that changes `threeStage`. It creates no camera/display calibration profile; all catalog HEX/XYZ claims remain absent and `approved:false`.
- `POST /api/sessions/{id}/camera-matches` accepts measured live target region/frames and bounded loop options, never a client-supplied target color or trusted completion. `/camera-matches/{runId}/observe` requires fresh actual video identities, rendered current command, camera-decoded marker and co-captured stable screen/fabric regions. Same 3-batch and evaluation budget limits apply; target drift pauses.
- `POST /api/sessions/{id}/neutral-check` accepts `{cards:[{role:"dark"|"middle"|"light",frames}],fingerprint}`. Exactly three unique roles, stable live native ROI geometry, fresh and same-image card evidence are required. Report is `limitedNeutralCheck`, `referenceValuesKnown:false`, `fullColorCalibration:false`, `cameraControlsApplied:false`; it does not invent reflectance/reference values or silently calibrate all colors.
- Experimental `cameraMatch` response profile: `POST /response-profile/start` takes fingerprint, native dimensions, streamId and actual canvas color space. The server owns eleven display steps with nine training and two held-out responses. `POST /response-profile/{runId}/observe` takes commanded screen+card co-captured Frame batches and the rendered command identity; `DELETE /response-profile` explicitly cancels. Native ROI, actual callback counter, timing span, decoded marker, witness drift and lifecycle revisions are checked. A zero reported media clock is preserved as unavailable, not synthesized.
- A valid measured response stores gamma, offset and cross-channel response in the declared camera RGB domain, not an ICC/XYZ profile. `live-preview` must send the same fingerprint and `canvasColorSpace`; its cameraAppearanceColorSpace is canonical sRGB from the tracking preview. Server conversion and bounded inverse produce display drive. Input `cameraAppearanceBands` stays separate from output bands. Outside-support, invalidated or expired profiles cannot issue compensated output; `compensatedOnly` requests fail closed without a usable profile. Independent physical validation remains `notTested`.
- `DELETE /api/sessions/{id}` deletes profiles, tokens, originals/crops and session metadata.
- `GET /api/schema` versioned entity + event schemas; `GET /api/health` local status; static originals not publicly exposed.
- `GET /api/connection-info` returns actual configured origin, HTTPS flag and optional public-CA setup availability. `/phone-setup` is operator instructions; `/phone-root-ca.crt` serves ONLY the designated public CA certificate, never keys or arbitrary paths. No automatic system-trust installation.

Frame = `{id:string, capturedAt:number, pixels:[[r,g,b],...], colorSpace:"srgb"|"display-p3", encoding:"encoded", blockIds:[int,...], pixelCount:int, excludedCount:int, source:"videoCanvas"|"replay", settingsFingerprint:string, markerSequence:null|int, markerPixels:null|[[r,g,b],...]}`. markerPixels are exactly 28 sampled black/white cells (4 sentinel + 24 bits). RGB float [0,1], up to 8192 samples/frame; 10 unique frames over >=1 sec default. Each block is a separated spatial subregion. `capturedAt` monotonic local milliseconds, not compared across devices. Local pixel selection sampling records counts, blockIds, masks; no lossy JPEG reencoding. Raw file pixels use ICC once then canonical tagged values. Region polygon and exclusion coordinates are normalized original-image [0,1], never display CSS pixels.

## WebSocket

`/ws/{sessionId}` requires exact Origin; first message within 5s `{event:"device.join",protocolVersion:1,sessionId,messageId,sequenceId:1,role:"camera"|"display",payload:{token}}`. Tokens never in query strings/logs. Each connection has increasing sequenceId, duplicate rejection, heartbeat deadline, bounded message sizes/rates. One active connection per role. Join emits session snapshot `session.state`; server event envelope has role server, protocolVersion, sessionId, messageId, sequenceId, payload. Subsequent client events:

- `capabilities.report` payload `{browserSupported,trackCapabilities,requested,reportedSettings,controlStatus,deviceLabel,capturePath,canvasColorSpace,wakeLock}`. Display or camera only its own report.
- `display.patch.set` camera payload `{profileVersion,patchId,displayDriveRgb:[0..1,0..1,0..1],layout:"single"|"group",sampleIds:[str]}`. Server generates `commandSequence`, markerSequence equals commandSequence, forwards to display and camera.
- `display.patch.rendered` display payload `{profileVersion,patchId,commandSequence,renderedAt}`. Server checks command and role. Two rAF only render request ACK, never physical proof.
- `session.pause` any role `{reason}`; pauses/invalidate current command. `session.resume` camera `{witnessChecked:true}`; reconnect never resumes automatically.
- `profile.invalidate` camera `{reason}` cascading invalidation.
- `heartbeat` any role `{localTime}` -> heartbeat. Timeout/disconnect pauses, no stale queue replay.
- `capture.request`, `quality.alert`, `match.iteration`, `match.complete`, `measurement.submit`, `camera.profile.ready`, `reference.set`, `export.request` server notices paired with relevant REST operations. Camera cannot supply trusted completed profiles/measurements through WS.

Display marker: 24-bit unsigned commandSequence, MSB first, 24 black/white cells, start sentinel black-white-black-white. Marker outside color patch. Camera operator selects marker rectangular ROI. Each bit sampled interior and decoded against sequence; oversized sequence rejected rather than truncated. Marker decode not OCR, no manual number-as-proof. Render region flat opaque color via rgb(), no CSS effects. Minimum patch dimension, stable border and layout recorded.

Additive implementation fields: Frame may include `presentedFrames`, `mediaTime`, native `width`/`height`, `regionId`, normalized `roi`/`exclusions`, `sharpnessStatus`. Known actual video identity is deduplicated per physical region; disjoint card ROIs can share the same original frame. Display observations require actual `cardFrames` paired with `cardPatchId` for full workflow, and display fit has `contaminationFabricBaseline`/`contaminationFabricChecks` alongside neutral witness controls. Patch-set `patches:[{sampleId,drive}]` renders genuinely different simultaneous cards; group-unverified is independent of single match. Strict current request/entity shapes are in generated schema; this prose is a workflow contract, not a substitute validator.

Per-live-measurement additive `cardPatchId`, `cardFrames`, `witnessFrames` pair physical witnesses from the same actual video images against stored profile baselines. Missing proof produces exploratory/limited output, never implicit referenced approval. Match-observe additionally requires `cardPatchId`, `cardFrames`, `fabricFrames`; the original sample stays stable against its frozen target. Actual video identity/native ROI metadata is mandatory for trusted display commands and match observations. A client-generated UUID or Boolean `witnessChecked` does not establish freshness or reuse validity.

## Engine Interface

`colorlab/engine.py` exports `decode_image(data:bytes, assumed_space=None)` -> dict `{rgb: numpy.ndarray HxWx3 float, metadata:{...}}`; `rgb_to_xyz(rgb,space="srgb")`, `xyz_to_lab(xyz,white="D65")`, `lab_to_xyz(lab,white="D65")`, `adapt_xyz(xyz,source="D50",target="D65")`, `delta_e00(lab1,lab2)`, `catalog_color(xyz)`; `summarize_frames(frames, min_frames=10, min_span_ms=1000)` -> `{rgb:[linear values],quality:{status,warnings,uniqueFrames,validPixels,validBlocks,excludedRate,temporalStd,blockSpread,...}}`; `fit_camera(target, observations)` -> dict profile `{id,status,matrix,trainingPatchIds,holdoutPatchIds,validation,...}`; `apply_camera(linear_rgb,profile)` -> XYZ D65 Y1; `fit_display(observations)` -> dict response profile; `suggest_bands(rgb,polygon,orientation)` -> Regions proposals; `extract_region(rgb,region)` -> summary/quality; `BoundedMatch(target,initial,noise_floor,max_evaluations,tolerance)` with `observe(response)` -> `{nextDrive,bestDrive,objectiveValue,iterations,status,terminationReason}`; `check_witness(baseline,current,noise_floor=0.002)` bool or explicit failure. No implicit clip of XYZ, source conversions only once.

## Verification and Limits

Tests first per vertical slice; numerical tests use published Sharma data and synthetic transforms; real JPGs test ICC/image geometry only, never physical color. Frozen human annotations are editable segmentation references, not inferred color truth. Camera control, illumination, brightness, independent instrument validation all unverified until real-device experiment. Unknown card/phone supported as explicit exploratory. Failure to achieve display match is not proof of out-of-gamut. Documentation must honestly list incomplete behavior.
