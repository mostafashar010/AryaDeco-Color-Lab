# AryaDeco Color Lab

ابزار مستقل محلی دوگوشی برای تخمین رنگ تحت شرایط ثبت‌شده. اسپکتروفتومتر نیست. هیچ اتصال یا مجوز نوشتن به سایت، MCP، دیتابیس یا زیرساخت آریادکو ندارد.

**حد تحویل:** کد اجرایی و مسیر سه‌مرحله‌ای موجود است، اما همهٔ بندهای پذیرش سند هنوز کامل نشده‌اند. تشخیص خودکار کارت شناخته‌شده و اعتبارسنجی فیزیکی نمایش گروهی موجود نیستند؛ ROI کارت دستی و نمایش گروهی با برچسب تأییدنشده موجودند. دستگاه/نور/ابزار واقعی آزموده نشده‌اند. جزئیات بدون ادعای تکمیل کاذب در `TEST_REPORT.md` آمده است.

## وضعیت علمی

- گوشی A فقط نمایشگر وصله‌ها است؛ گوشی B دوربین و کنترل‌کننده.
- ترتیب سه‌مرحله‌ای: مشخصه‌یابی دوربین با کارت فیزیکی، پاسخ نمایشگر کنار همان کارت، سنجش نمونه و تطبیق حلقه‌بسته.
- `catalogHexSrgb` تخمین ظاهر نمونه برای سایت است؛ `displayDriveRgb` فرمان مخصوص نمایشگر این جلسه. تغییر فرمان صفحه هیچ‌وقت رنگ کاتالوگ را بازنویسی نمی‌کند.
- اطلاعات کارت، نور، گوشی، قفل تنظیمات و روشنایی اگر معلوم نیستند، نامعلوم می‌مانند. خاکستری ۱۸٪ خودکار `#808080` نیست؛ رنگ چاپی یا شمارهٔ کالیته مرجع Lab/XYZ نیست.
- اختلاف صفحه/پارچه از دید همان دوربین تأیید مستقل رنگ واقعی نیست. `instrumentDeltaE00` بدون سنجش ابزار مستقل `null` است. نتایج آزمون نرم‌افزار در `TEST_REPORT.md` جدا از آزمون سخت‌افزار ثبت می‌شوند.

تخمین `referenced` نیز به‌تنهایی رنگ تأییدشدهٔ فروشگاه نیست. سیاست نسخهٔ فعلی تا نبود کنترل فیزیکی معتبر و شواهد کافی، `approved:false` می‌دهد؛ انتخاب خروجی approved رنگ را خودکار ارتقا نمی‌دهد. کیفیت برداشت، اعتبار رنگ کاتالوگ، تطبیق نمایشگر و تأیید مستقل چهار وضعیت جدا هستند. دادهٔ مفید ولی محدود در خروجی experimental می‌ماند.

## نصب محلی

محیط توسعهٔ بررسی‌شده: Python 3.12.3 و Node 22.23.1. نسخه‌های وابستگی پایتون در `requirements.lock` و رابط در `frontend/package-lock.json` قفل می‌شوند. محیط مجازی محلی و `node_modules` جزو کد تحویل نیستند.

```bash
python3 -m venv /home/betoche/go/GOLD_PROJECT/GoLang_P/AryaDeco-Color-Lab/.venv
/home/betoche/go/GOLD_PROJECT/GoLang_P/AryaDeco-Color-Lab/.venv/bin/pip install -r /home/betoche/go/GOLD_PROJECT/GoLang_P/AryaDeco-Color-Lab/requirements.lock
npm --prefix /home/betoche/go/GOLD_PROJECT/GoLang_P/AryaDeco-Color-Lab/frontend ci
npm --prefix /home/betoche/go/GOLD_PROJECT/GoLang_P/AryaDeco-Color-Lab/frontend run build
```

اجرای معمول برای لپ‌تاپ و دو گوشی، بدون پارامتر تکراری:

```bash
/home/betoche/go/GOLD_PROJECT/GoLang_P/AryaDeco-Color-Lab/.venv/bin/python /home/betoche/go/GOLD_PROJECT/GoLang_P/AryaDeco-Color-Lab/run.py
```

سرور پیش‌فرض اکنون روی **`0.0.0.0:8443` با HTTPS** است. IP شبکهٔ Wi-Fi/Ethernet تشخیص داده و آدرس دقیق در ترمینال چاپ می‌شود؛ در بررسی فعلی `https://192.168.8.8:8443` است. روی لپ‌تاپ و هر دو گوشی همین آدرس را باز کنید؛ `0.0.0.0` آدرس شنود است، نه آدرسی که روی گوشی وارد شود. گواهی CA و کلید خصوصی در `certs/` نگه داشته و دوباره استفاده می‌شوند؛ تغییر IP فقط گواهی سرور را با همان CA تجدید می‌کند. برنامه اعتماد سیستم‌عامل را تغییر نمی‌دهد.

اجرای توسعهٔ قبلی فقط روی لپ‌تاپ: همان فرمان را با `--local` اجرا کنید، سپس `http://localhost:8443` را باز کنید. اگر تشخیص IP ممکن نبود، `--lan-ip 192.168.8.8` را با IP واقعی وارد کنید. پورت دلخواه با `--port` قابل تعیین است. تنظیمات آمادهٔ شخصی نیز با `--config /absolute/path/server.json` و کلیدهای `version:1`، `host`، `port`، `origin`، `cert`، `key` قابل خواندن است؛ مسیر گواهی نسبت به همان فایل تفسیر می‌شود.

## HTTPS روی دو گوشی

**راه سادهٔ پیش‌فرض:** پس از اجرای برنامه، `https://192.168.8.8:8443/phone-setup` را با IP چاپ‌شده در ترمینال باز کنید. گواهی عمومی را دریافت و فقط یک‌بار روی هر گوشی نصب/مورد اعتماد کنید. صفحهٔ راه‌اندازی، مراحل Android/iPhone را توضیح می‌دهد. SHA-256 fingerprint گواهی در ترمینال چاپ می‌شود؛ منبع و fingerprint را تطبیق دهید. فقط فایل `phone-root-ca.crt` عمومی قابل دریافت است؛ هیچ فایل `.key` از وب منتشر نمی‌شود. این CA محلی اختیار اعتماد دارد؛ صرفاً برای لپ‌تاپ مورد اعتماد استفاده و پس از عدم نیاز از گوشی حذف کنید. دورزدن موقت هشدار صفحه برای دریافت CA، معادل مورد اعتماد شدن دوربین نیست.

روش زیر برای استفاده از گواهی mkcert یا گواهی شخصی جایگزین است؛ در مسیر خودکار به نصب mkcert یا اجرای این فرمان‌ها نیاز نیست.

هر دو گوشی و کامپیوتر در شبکهٔ محلی قابل دسترس باشند. یک IP ثابت/رزروشده برای کامپیوتر تعیین کنید. مثال زیر `192.168.1.23` است و باید با IP واقعی کامپیوتر جایگزین شود؛ سازگاری گوشی یا امکان دسترسی شبکه از قبل اثبات نشده است.

گواهی باید برای همان IP یا نام میزبان صادر شده و زنجیرهٔ آن روی هر دو گوشی مورد اعتماد باشد. فقط عبور از هشدار گواهی، آزمون موفق HTTPS یا دوربین محسوب نمی‌شود. راهنمای رسمی mkcert: https://github.com/FiloSottile/mkcert . نصب mkcert و اعتماد به CA، تصمیم اپراتور است؛ برنامه آن را انجام نمی‌دهد.

نمونه پس از نصب mkcert و بررسی محل پروژه:

```bash
mkdir -p /home/betoche/go/GOLD_PROJECT/GoLang_P/AryaDeco-Color-Lab/certs
mkcert -install
mkcert -cert-file /home/betoche/go/GOLD_PROJECT/GoLang_P/AryaDeco-Color-Lab/certs/lab.pem -key-file /home/betoche/go/GOLD_PROJECT/GoLang_P/AryaDeco-Color-Lab/certs/lab-key.pem 192.168.1.23 localhost 127.0.0.1
chmod 600 /home/betoche/go/GOLD_PROJECT/GoLang_P/AryaDeco-Color-Lab/certs/lab-key.pem
mkcert -CAROOT
```

تنها فایل عمومی `rootCA.pem` در مسیر `CAROOT` را برای اعتماد روی گوشی نصب کنید. **`rootCA-key.pem` یا `lab-key.pem` را هرگز به گوشی، مخزن یا شخص دیگری منتقل نکنید.** روش نصب و فعال‌کردن اعتماد کامل به نسخهٔ سیستم‌عامل بستگی دارد؛ برخی دستگاه‌های سازمانی اجازهٔ CA کاربر نمی‌دهند. روی iOS نصب پروفایل و فعال‌کردن اعتماد کامل دو مرحلهٔ جدا هستند؛ روی Android نیز اعتماد مرورگر باید عملاً بررسی شود. پس از پایان کار، CA آزمایشی را در صورت عدم نیاز حذف کنید.

اجرای صریح برای شبکهٔ محلی:

```bash
/home/betoche/go/GOLD_PROJECT/GoLang_P/AryaDeco-Color-Lab/.venv/bin/python /home/betoche/go/GOLD_PROJECT/GoLang_P/AryaDeco-Color-Lab/run.py --host 0.0.0.0 --port 8443 --origin https://192.168.1.23:8443 --cert /home/betoche/go/GOLD_PROJECT/GoLang_P/AryaDeco-Color-Lab/certs/lab.pem --key /home/betoche/go/GOLD_PROJECT/GoLang_P/AryaDeco-Color-Lab/certs/lab-key.pem
```

این دستور فقط به درخواست اپراتور اجرا شود. پورت را روی اینترنت forward نکنید. هر دو گوشی باید دقیقاً `https://192.168.1.23:8443` را باز کنند؛ نام دیگر یا پورت دیگر Origin متفاوت است و پذیرفته نمی‌شود. در صورت firewall، دسترسی فقط از شبکهٔ محلی قابل اعتماد بررسی شود، نه با خاموش‌کردن کلی firewall.

## پروتکل اپراتور

### مسیر سادهٔ زنده و خودکار

**جبران پاسخ نمایشگر، قبل از نمایش نوارها:** در حالت ساده، پس از اتصال A و بازکردن دوربین B، «اندازه‌گیری پاسخ نمایشگر» را بزنید. سه کارت را جدا و قابل‌دیدن، کنار A قرار دهید؛ کارت خاکستری میانی شاهد تمام مراحل است. A باید عمودی و نشانگر پایینش کامل دیده شود. برنامه ۱۱ فرمان مستقل شامل خاکستری‌ها و رنگ‌های آزمون را نمایش می‌دهد و صفحه و کارت را در همان فریم‌ها ثبت می‌کند. دو فرمان فقط برای ارزیابی نگه داشته می‌شوند. لازم نیست برای هر فرمان کارت رنگی نامعلوم بسازید یا عوض کنید؛ شاهد واقعی ثابت بماند.

پس از پیام «مدل آماده»، «نمایش زندهٔ کالیته» از مدل اندازه‌گیری‌شده استفاده می‌کند. روی A عبارت «پاسخ نمایشگر جبران شده؛ از دید دوربین، آزمایشی» دیده می‌شود؛ در نبود مدل، صریحاً «RGB دوربین بدون جبران پاسخ نمایشگر» نمایش داده می‌شود. ورودی appearance دوربین از فرمان خروجی مستقل است. تغییر تنظیم دوربین، روشنایی/شرایط صفحه، ابعاد، فضای رنگ یا جلسه نیازمند پاسخ تازه است. رنگ هدف خارج از پوشش مدل یا ارزیابی ناموفق به فرمان جبران‌شده ارتقا داده نمی‌شود.

**این مدل ICC یا تضمین ۱۰۰٪ برابری با چشم نیست.** مدل، پاسخ غیرخطی/اختلاط کانال‌های A را از دید B جبران می‌کند. کارت خاکستریِ فاقد مقادیر معتبر صرفاً شاهد ثبات است؛ Lab/XYZ، ۱۸٪، دقت ابزار مستقل یا قفل firmware از آن فرض نمی‌شود. برای اعتبار رنگ فیزیکی به مرجع معتبر و ارزیابی مستقل در نور و هندسهٔ مشخص نیاز است. `catalogHexSrgb` در این مسیر همچنان `null` می‌ماند. روی مرورگر با `mediaTime=0` برداشت نسبی فقط برای این مدل آزمایشی مجاز است؛ اندازه‌گیری علمی اصلی از ساعت ساختگی استفاده نمی‌کند.

برای جلوگیری از تشخیص‌نشدن، نشانگر A بزرگ‌تر شده است. نشان بسیار کوچک/کج یا A چرخیدهٔ ۹۰ درجه، هنوز مجوز سنجش نمی‌دهد و پیام اصلاح قاب نشان می‌دهد. کالیتهٔ پنهان پشت جسم بازسازی نمی‌شود. لبهٔ چین یا خط روشنِ روی تصویر، در صورت ابهام، «مرز نامطمئن» است، نه تعداد قطعی نمونه‌های فیزیکی.

اگر تشخیص خودکار صفحه یا کارت برای سنجش پاسخ گیر کرد، گزینهٔ «تعیین دستی صفحه و کارت» مسیر جایگزین دارد: وصلهٔ راه‌اندازی روی A نمایش داده می‌شود؛ داخل سطح رنگی و داخل همان کارت خاکستری را جدا رسم و تأیید کنید و نوار نشانگر را کامل انتخاب کنید. سپس پاسخ را با ناحیه‌های انتخاب‌شده اندازه بگیرید. انتخاب دستی فقط هندسه را تعیین می‌کند؛ نشانگر واقعی فرمان، ده فریم هم‌زمان، ثبات شاهد و ارزیابی مدل همچنان لازم‌اند. دوربین و کارت باید ثابت بمانند؛ هیچ مرحله‌ای با یک تأیید دستی به کالیبراسیون معتبر ارتقا نمی‌یابد.

**برای نمایش پیوستهٔ رنگ نوارها مثل آفتاب‌پرست:** دوربین را باز کنید و **«نمایش زندهٔ کالیته»** را بزنید. گوشی A ابتدا صفحهٔ شناسایی با نشانگر نشان می‌دهد؛ سپس نوارهای دیده‌شدهٔ پارچه روی آن به‌روز می‌شوند. گوشی A می‌تواند چپ یا راست باشد. کارت‌های روی کالیته از نمونه‌برداری کنار گذاشته می‌شوند؛ قسمت پنهان پارچه بازسازی نمی‌شود. هنگام حرکت دوربین پیش‌نمایش ادامه دارد، ولی اندازه‌گیری دقیق معتبر تلقی نمی‌شود. نوار سیاه‌وسفید A باید دیده شود تا رنگ خود صفحه دوباره به‌اشتباه از پارچه نمونه‌برداری نشود.

در نسخهٔ بازخورد چندنوار، رنگ داخل هر نوار صفحه و نوار پارچه از همان فریم نمونه‌برداری می‌شود. فقط فرمان رندرشده با نشانگر واقعی مطابق و قاب پایدار اجازهٔ اصلاح دارد. برای هر نوار چند بلوک داخلی بررسی می‌شود؛ ناحیهٔ کوچک، کلیپ یا اختلاف مکانی زیاد به بازخورد پذیرفته‌شده تبدیل نمی‌شود. فرمانِ بدون تغییر برای مدت کوتاهی حفظ می‌شود تا دوربین فرصت دیدن آن را داشته باشد؛ صف قدیمی انباشته نمی‌شود.

عبارت «بازخورد اندازه‌گیری‌شدهٔ صفحه، آزمایشی» یعنی اصلاح از مشاهدهٔ صفحه صادر شده است؛ «جبران مدل پاسخ» فقط پیش‌بینی مدل است و «پیش‌نمایش خام» هنوز بازخورد ندارد. خطای نمایش‌داده‌شده فاصله در RGB خطی دوربین **پیش از اصلاح** است، نه درصد شباهت با چشم یا ΔE ابزار مستقل. کاهش خطا باید در فریم بعدی دیده شود. نوار خارج پوشش مدل، باقی نوارها را متوقف نمی‌کند و وضعیت بدون جبران خودش را دارد؛ توقف کاهش خطا و محدودیت فرمان جدا گزارش می‌شوند. تغییر پارچه، هندسه یا فضای رنگ اصلاح قبلی را نامعتبر می‌کند.

این قابلیت «ظاهر رنگ در دوربین» است، نه نتیجهٔ کالیبره. هم‌ترازی عمودی از محدودهٔ مشاهده‌شدهٔ صفحه تخمین زده می‌شود و زاویه/پرسپکتیو تأیید نشده‌اند. «تطبیق دقیق آزمایشی» قابلیت جدا برای برداشت ثابت و حلقهٔ محدود است، نه الزام شروع پیش‌نمایش.

برای تطبیق دو گوشی بدون انتخاب ناحیه و بدون عکس‌گرفتن، قابلیت **«تطبیق زندهٔ ساده، بدون کارت»** را انتخاب کنید. اسم این قابلیت یعنی مرجع عددی استاندارد لازم ندارد؛ بررسی سه کارت تیره/میانی/روشن شما همچنان ابتدا پیشنهاد می‌شود. این حالت `cameraMatch` جدا از کالیبراسیون سه‌مرحله‌ای است و هیچ HEX تأییدشدهٔ سایت تولید نمی‌کند.

1. گوشی A را با QR وصل و صفحه‌اش را باز نگه دارید. همهٔ کارهای بعدی روی گوشی B است.
2. روی B **«بازکردن دوربین و دیدن کادر»** را بزنید و مجوز دوربین را بدهید. ابتدا فقط تصویر زنده باز می‌شود؛ اندازه‌گیری و بررسی کارت شروع نشده است. سه کارت را جدا و کامل داخل قاب بگذارید؛ در مرحلهٔ کارت‌ها گوشی A و کالیته را کنار قاب کارت‌ها بگذارید، نه روی آن‌ها.
3. کادرهای تشخیص روی تصویر به‌روز می‌شوند؛ نامزدهای ناقص برچسب تأییدنشده دارند. پس از سه تشخیص پایدار، **«شروع بررسی همین قاب»** فعال می‌شود. با زدن آن از هر سه سطح داخلی هم‌زمان فریم تازه گرفته می‌شود؛ رسم مستطیل یا انتخاب شناسه لازم نیست.
4. وقتی صفحه گفت «حالا پارچه را چپ و گوشی نمایشگر را راست قاب بگذارید»، چیدمان را تغییر دهید. نشان سیاه‌وسفید A باید کامل، مستقیم و به‌اندازهٔ کافی بزرگ دیده شود. ردیابی زنده می‌ماند؛ فریم هنگام حرکت، اندازه‌گیری معتبر نیست.
5. پس از ثابت‌شدن تصویر، دوباره **«شروع بررسی همین قاب»** را بزنید. برنامه نوارها، صفحه و نشان را پیدا می‌کند، از ویدئوی باز نمونه می‌گیرد، رنگ صفحه را عوض می‌کند و نمونه‌ها را پشت‌سرهم تطبیق می‌دهد. عکس دستی یا فرمان تطبیق جدا برای هر نوار لازم نیست.
6. اگر تشخیص مبهم باشد، همان‌جا تعداد کاندیدها و علت رد را می‌بینید. حرکت، تغییر سطح، فریم کهنه یا قطع ارتباط اندازه‌گیری را لغو می‌کند ولی پیش‌نمایش باقی می‌ماند. بعد از ثابت‌شدن، شروع مجدد صریح است؛ ادامهٔ مخفیانه نداریم.

### ردگیری مشکل

در پنل **«شواهد تشخیصی رنگ»** سه لایه جدا نمایش داده می‌شود: فرمان RGB سرور، رنگ CSS گرد‌شدهٔ گوشی A پس از دو فریم رندر، و رنگ مشاهده‌شدهٔ دوربین B. شمارهٔ فرمان، شمارهٔ فریم، زمان خام، ابعاد native/analysis، ناحیه‌ها، کیفیت نمونه و علت رد ثبت می‌شوند. دو فریم رندر، اثبات نور یا رنگ فیزیکی نمایشگر نیست. اختلاف RGB فقط با فرمان و نشانگر یکسان، نوارهای همسان و نمونه‌های واجد کیفیت نشان داده می‌شود؛ نبود اختلاف در پنل به معنی صفر بودن خطا نیست.

دیباگ تصویری، هویت فریم تصویر را از هویت تحلیل جدا نگه می‌دارد. اگر `trackingMatchedFrame:false` باشد، تصویر به تحلیل همان فریم متصل نیست و شمارش اشیا یا وضعیت قدیمی به آن نسبت داده نمی‌شود. زمان خام صفر حفظ می‌شود. تصاویر همچنان فقط با رضایت، حداکثر هشت فریم و پنج دقیقه نگهداری می‌شوند؛ توکن و تصویر وارد لاگ عددی نمی‌شوند. خاموش/روشن‌کردن ثبت، تاریخچهٔ زمان خاموشی یا جلسهٔ قبلی را ارسال نمی‌کند.

مشکی و نزدیک‌مشکیِ دارای مرز معتبر می‌تواند در پیش‌نمایش باقی بماند؛ مقدار صفر یا کلیپ‌شدن روشنایی دوربین، مدرک رنگ دقیق نیست و با علت مشخص از بازخورد کنار گذاشته می‌شود. نوار تیرهٔ بازیابی‌شده، هندسهٔ پیشنهادی است و با سایه ممکن است مبهم باشد. کاهش خطای کوچک در رنگ تیره دیگر به‌طور خودکار «توقف پیشرفت» محسوب نمی‌شود.

**ثبت خودکار:** رویدادهای کنترل‌شده هر چند ثانیه بدون دانلود دستی روی لپ‌تاپ ذخیره می‌شوند. پنل، وضعیت ذخیره و شناسهٔ آزمایش را نشان می‌دهد. فایل‌ها در `data/diagnostics/*.jsonl` خصوصی هستند؛ بدون عکس، پیکسل خام، توکن، متن آزاد و دادهٔ سایت. هر فایل حداکثر ۱ MiB و کل مجموعه حداکثر ۳۲ MiB است. انقضای جلسه گزارش را برای بررسی باقی می‌گذارد؛ حذف صریح جلسه گزارش همان جلسه را هم پاک می‌کند. گزینهٔ غیرفعال‌سازی/حذف گزارش در API موجود است. این گزارش به‌تنهایی تصویر یا صحت علمی رنگ را اثبات نمی‌کند.

پنل **«عیب‌یابی زنده»** کنار پیش‌نمایش، مرحلهٔ فعلی، تعداد کارت/نامزد/نمونه، نشانگر، هویت فریم، ثبات و فرمان/ACK نمایشگر را نشان می‌دهد. با **«دریافت ردگیری JSON»** گزارش ۳۰۰ رویداد آخر را بگیرید. این گزارش محلی است، خاموشی/رد/خطای API و ترتیب مراحل را ثبت می‌کند؛ تصویر و ویدئو و پیکسل خام صادر نمی‌شود. فیلدهای توکن و کدهای ناشناخته حذف می‌شوند؛ متن آزاد گزارش گواهی امنیتی مستقل ندارد. این گزارش با export رنگ متفاوت است و هیچ اندازه‌گیری فیزیکی یا صحت رنگ را اثبات نمی‌کند.

ردیابی در worker و با یک پردازش هم‌زمان اجرا می‌شود؛ هدف حدود دو به‌روزرسانی هندسه در ثانیه است و روی دستگاه کند کاهش می‌یابد، نه تضمین تشخیص ۳۰ فریم در ثانیه. ویدئو با نرخ گزارش‌شدهٔ واقعی خودش نمایش داده می‌شود. حرکت و تغییر نور/ظاهر ممکن است به یک توقف محافظه‌کارانه منتهی شود؛ پیام حرکت، اثبات علت فیزیکی قطعی نیست.

**مرورگر دارای زمان ویدئوی ثابت:** در لاگ گوشی‌های مالک، `mediaTime` همیشه صفر بود. پیش‌نمایش اکنون با شمارندهٔ واقعیِ افزایشی callback ادامه می‌یابد و مقدار گزارش‌شدهٔ صفر حفظ می‌شود؛ زمان جایگزین به‌عنوان زمان واقعی ویدئو معرفی نمی‌شود. ردیابی/نمایش آزمایشی کار می‌کند، اما هندسهٔ آن برای اندازه‌گیری دقیق `fresh` تأیید نمی‌شود. اگر برداشت دقیق بخواهید، همان‌جا پیام «زمان ویدئو ثابت گزارش می‌شود» ظاهر می‌شود؛ به‌جای هنگ‌کردن بی‌توضیح.

پردازش کند، worker را برای همیشه خاموش نمی‌کند؛ وضوح تحلیل کاهش و پردازش دوباره راه‌اندازی می‌شود. پاسخ خارج از مهلت تازگی برای سنجش دقیق معتبر نیست. هنگام انتظار، تعداد آخرین نامزدها با برچسب UNKNOWN دیده می‌شود، نه صفر کاذب ناشی از تایمر. ضربان پردازش تعداد callback، تحلیل شروع/تکمیل، مدت، وضوح و retry را نشان می‌دهد و این اعداد محدود در گزارش خودکار ذخیره می‌شوند.

حالت «اندازه‌گیری کامل با کارت معتبر» موتور تشخیص قوی‌تر یا تنظیمِ تضمینی خودکار گوشی نیست؛ مسیر علمی با مرجع چندرنگ معتبر است. سه کارت خنثی شما برای کنترل محدود بررسی می‌شوند، ولی بدون مقادیر مرجع، کالیبراسیون کامل ایجاد نمی‌کنند. برای نمایش آفتاب‌پرستی، قابلیت پیش‌نمایش آزمایشی را صریح انتخاب کنید؛ دکمهٔ داخل حالت کامل جلسهٔ جداگانه و QR جدید می‌سازد، بدون تغییر اعتبار پروفایل قبلی.

«ادامه بدون کارت، آزمایشی» یک انتخاب صریح برای رد کردن بررسی کارت‌ها است، نه کالیبراسیون موفق. کارت‌های موجود فقط با روشنایی مشاهده‌شده نام‌گذاری می‌شوند؛ استاندارد، ۱۸٪، Lab/XYZ یا قفل واقعی دوربین از عکس فرض نمی‌شود. بررسی کارت‌ها نسبت کانال‌ها و ثبات را ثبت می‌کند؛ برنامه در این مسیر ادعای تنظیم قطعی سخت‌افزار یا صحت مطلق رنگ ندارد. `catalogHexSrgb` در این قابلیت همیشه `null` است؛ فرمان صفحه مستقل می‌ماند.

تشخیص خودکار به چیدمان واضح، کارت‌های جدا، نوارهای قابل تفکیک و نشان مستقیم وابسته است. جنس پارچه از مستطیل‌های رنگی اثبات نمی‌شود. مسیر کاملِ مرجع‌دار به مقادیر و چیدمان واقعاً معتبر نیاز دارد؛ سه کارت خنثی به‌تنهایی ماتریس کامل رنگ را نمی‌سازند. کنترل‌های قدیمی برای متخصص در «تنظیمات کامل» حفظ شده‌اند، ولی کاربر مسیر ساده نباید از آن‌ها استفاده کند. حالت خودکار «فقط کاتالوگ» هنوز جداگانه کامل نشده است.

### مسیر مرجع‌دار تخصصی

فرم شرایط، ثبت‌نام نیست و برای شروع لازم نیست هر بار آن را پر کنید. اطلاعات اختیاری در بخش جمع‌شونده قرار دارند؛ با فعال‌بودن نگهداری تنظیمات، مقادیر واردشده روی همین مرورگر برای دفعهٔ بعد می‌مانند. گزینهٔ پاک‌کردن تنظیمات فقط همین پیش‌فرض‌ها را حذف می‌کند، نه اندازه‌گیری‌های جلسه. توکن، تصویر، پروفایل و کالیبراسیون در این ذخیره‌سازی نگهداری نمی‌شوند. روشنایی/نور/زمینهٔ ذخیره‌شده تأیید فعلی نیست؛ در صورت تغییر، مقدار را اصلاح کنید. ذخیره‌سازی به Origin وابسته است؛ انتقال از `localhost` به IP یا تغییر پورت، محل ذخیرهٔ مرورگر دیگری محسوب می‌شود.

1. گوشی B صفحهٔ اصلی را باز کند؛ حالت `سه‌مرحله‌ای` را انتخاب و اطلاعات نامعلوم را صریح ثبت کند. مشخصات کارت، منبع معتبر Lab/XYZ، مشاهده‌گر، سفید مرجع، نور گزارش‌شده، زمینه، لایه‌ها و جهت بافت را وارد کند.
2. گوشی A پیوند/QR نقش نمایشگر را باز کند. این پیوند کوتاه‌عمر محرمانه است؛ آن را روی سایت یا پیام عمومی نگذارید. دوربین فقط با اجازهٔ کاربر و بدون میکروفن فعال می‌شود.
3. گام صفر: شاهد خنثی و صفحه را در قاب قرار دهید. ROI شاهد، صفحه و نشان باینری خارج از وصله را تعیین کنید. تنظیمات درخواست‌شده، قابلیت Track و تنظیمات گزارش‌شده جدا هستند؛ موفقیت `applyConstraints` به‌تنهایی اثبات قفل فیزیکی نیست.
4. دوربین/لنز/نور/زمینه ثابت؛ لنز و صفحه تمیز؛ بازتاب دیوار/فرش، سایهٔ دست و نور مخلوط حذف شوند. برای حریر زمینه و تعداد لایه تعریف شود، برای بافت جهت‌دار جهت ثبت شود. عکس سفید و مشکی دو برداشت مستقل‌اند.
5. مرحلهٔ دوربین: فایل مرجع را وارد و شناسهٔ فیزیکی هر وصله را با ROI داخل آن تطبیق دهید. وصله‌های ارزیابی از آموزش کنار گذاشته شوند. سه کارت خنثی، پروفایل کامل رنگ نمی‌سازند. مرجع نامعتبر/کم‌رتبه مسیر اکتشافی است، نه کالیبراسیون معتبر.
6. مرحلهٔ نمایشگر: کارت فیزیکی کنار صفحه در قاب بماند. تنظیم روشنایی با اپراتور انجام و سپس ثابت شود؛ برنامه روشنایی سیستم‌عامل را کنترل نمی‌کند. رنگ‌های کنترل نمایش داده شوند و ثبات شاهد/نمونه سنجیده شود؛ اگر رنگ صفحه هدف را جابه‌جا کرد، توقف و تغییر فاصله/نور/مانع مات لازم است. علت تغییر خودکار قطعی تعیین نمی‌شود.
7. صفحهٔ A نشان فرمان را خارج از ناحیهٔ اندازه‌گیری نشان می‌دهد. دریافت پیام و دو `requestAnimationFrame` فقط تأیید درخواست رندر است؛ دیدن نشان همان فرمان در فریم دوربین، تثبیت و چند فریم تازه همچنان لازم است. سری پاسخ صفحه و رنگ‌های کنارگذاشته‌شدهٔ ارزیابی گرفته شوند.
8. مرحلهٔ پارچه: هر نوار مستقل شناسه و ترتیب خود را دارد. مرزهای پیشنهادی کمک‌یارند؛ متر، برچسب، چین مرزی و پس‌زمینه باید بیرون ماسک باشند. رنگ‌های نزدیک را فقط به‌سبب شباهت ادغام نکنید. انتخاب اصلی روی دادهٔ اصلی و ماسک قابل بازبینی است.
9. هر سنجش چند بلوک داخلی و پیش‌فرض حداقل ۱۰ فریم یکتا طی حداقل یک ثانیه نیاز دارد. پیکسل سوخته و ناحیهٔ کوچک/ناپایدار به بازبرداشت منتهی می‌شوند، نه بازسازی خیالی. آستانه‌ها سیاست شروع مهندسی‌اند، نه درصد دقت یا استاندارد آزمایشگاه.
10. حلقهٔ هر نمونه فقط با فرمان تازه، تأیید رندر، نشان صحیح و شاهد پایدار جلو می‌رود. توقف، قطعی، تغییر تنظیمات و برگشت از پس‌زمینه نیازمند بازبینی و ادامهٔ صریح هستند. بهترین فرمان و دلیل توقف حفظ می‌شود؛ عدم همگرایی لزوماً خارج‌ازگاموت نیست.
11. رنگ کاتالوگ و نتیجهٔ صفحه جدا بازبینی و JSON/CSV گرفته شوند. خروجی آزمایشی با خروجی پذیرفته‌شده اشتباه نشود؛ نمونهٔ شکست‌خورده در گزارش می‌ماند. تطبیق تکی، اعتبار چیدمان گروهی را ثابت نمی‌کند.

دوربین پیش‌فرض فقط `environment` درخواست می‌کند؛ در صورت نبود آن، برنامه لنز دیگری را مخفیانه جایگزین نمی‌کند. دکمهٔ «فهرست دوربین‌ها» امکان انتخاب صریح دستگاه را می‌دهد؛ نام دوربین پیش از مجوز ممکن است خالی باشد. مسیر فعلی برای سنجش زنده به canvas float و `requestVideoFrameCallback` نیاز دارد؛ دستگاه فاقد این مسیر با پیام محدودیت متوقف می‌شود، نه با ادعای سازگاری قطعی یا کاهش کیفیت بی‌خبر.

نمونه‌برداری زندهٔ دارای مرجع به کارت و شاهد خنثی هم‌زمان نیاز دارد. نبود شواهد کافی، خروجی را `exploratory` می‌کند حتی اگر ماتریس دوربین قبلاً برازش شده باشد. حلقهٔ صفحه نیز کارت، شاهد و خود پارچه را در همان فریم نگه می‌دارد؛ تغییر پارچه/نور اجازهٔ ادامه با هدف قدیمی را نمی‌دهد. امضای تنظیمات و شاهدها جای قفل تضمینی firmware نیستند.

## عکس‌های مرجع و بازپخش

`references/01-striped-sheer.jpg` و `references/02-swatch-bands.jpg` نسخهٔ بدون تغییر فایل‌های کاربرند. متادیتای واقعی اولی sRGB و دومی Display P3 است. این تصاویر برای آزمون decode و ناحیه‌بندی‌اند، نه HEX فیزیکی قابل تأیید. نگاشت مرجع و ماسک‌های پیشنهادی باید روی دستگاه بازبینی شوند؛ لبهٔ ناقص تصویر به‌عنوان نمونهٔ کامل تلقی نمی‌شود.

در حالت بازپخش، بارگذاری عکس کامل اقدامی صریح است؛ موتور اصلی سرور ICC را می‌خواند. پیش‌نمایش canonical sRGB دوباره با ICC اصلی P3 تبدیل نمی‌شود. نبود ICC باید برچسب فرض/اکتشافی بگیرد؛ ICC ناشناخته بی‌خبر حذف نمی‌شود. ویدئوی کامل به سرور ارسال نمی‌شود؛ برداشت زنده وصله‌های لازم و اطلاعات نمونه‌برداری را منتقل می‌کند، نه RAW سنسور.

مسیر فعلی ICC پروفایل RGB نوع matrix/TRC را می‌خواند؛ ICC نوع LUT و CMYK صریحاً پشتیبانی نمی‌شوند و رد می‌شوند. EXIF orientation در provenance ثبت می‌شود؛ پیش‌نمایش سرور بر مختصات پیکسل اصلی باقی می‌ماند و چرخش خودکار EXIF انجام نمی‌دهد. سنجش و ماسک باید بر همان پیش‌نمایش اصلی باشند، نه نمایی که نرم‌افزار دیگری خودکار چرخانده است.

## حریم خصوصی و داده

یک نمونهٔ سرور و یک دستگاه فعال برای هر نقش. توکن نقش نمایشگر اجازهٔ تولید نتیجهٔ دوربین یا خروجی کاتالوگ ندارد. هیچ سرویس مولد/رهگیری/سرویس رنگ پولی در هسته نیست. تصویر و توکن در access log ثبت نمی‌شوند. بارگذاری تصاویر کامل اختیاری است؛ حذف جلسه باید تمام دادهٔ همان جلسه و توکن‌ها را حذف کند. پیش از خاموش‌کردن سرور JSON را صادر کنید؛ بازیابی خودکار سنجش زنده از وضعیت قدیمی مجاز نیست.

قرارداد API و مدل‌ها در `CONTRACT.md` و schema تولیدشده در `/api/schema` ارائه می‌شوند. endpoint `/api/health` فقط آمادگی سرویس را می‌سنجد، نه آمادگی فیزیکی دو گوشی. جزئیات ویژگی‌های تحویل‌شده و محدودیت‌ها در گزارش آزمون ثبت می‌شود.

مدت و سقف جلسه محدودند؛ دادهٔ جلسهٔ زنده در حافظهٔ همین تک‌فرایند است. حذف جلسه داده‌های درون‌حافظه و تصویر همان جلسه را حذف می‌کند، ولی فایل JSON/CSV دانلودشده روی دستگاه را از دور پاک نمی‌کند. فایل اصلی با فیلد multipart به‌نام `retention` و مقدار `false` پیش‌فرض ذخیرهٔ ماندگار نمی‌شود؛ پردازش/پیش‌نمایش خصوصی تا حذف یا پایان جلسه نیازمند دادهٔ decodeشده است. توکن نمایشگر با دوربین قابل تعویض نیست. پیوند دوربین در صورت ازبین‌رفتن توکن، از طریق دورزدن احراز هویت بازیابی نمی‌شود.

## گزارش اعتبارسنجی مستقل

ابزار `tools/validation_report.py` فایل JSON صریح اپراتور را از ورودی استاندارد می‌گیرد و گزارش را چاپ می‌کند؛ هیچ نتیجهٔ اصلی را بازنویسی نمی‌کند. سه نوع `repeatability`، `reacquisition` و `instrument` دارد. ورودی تکرارپذیری شامل `samples` با `captureId`، `placementId` و `lab`، همراه `referenceWhite` و `observer` است. حداقل ۱۰ شناسهٔ برداشت و جای‌گذاری مستقل لازم است؛ صداقت استقلال با اپراتور است و نرم‌افزار آن را فیزیکی اثبات نمی‌کند.

```bash
/home/betoche/go/GOLD_PROJECT/GoLang_P/AryaDeco-Color-Lab/.venv/bin/python /home/betoche/go/GOLD_PROJECT/GoLang_P/AryaDeco-Color-Lab/tools/validation_report.py repeatability < /absolute/path/operator-repeatability.json
```

بازبرداشت `original` و `observed` را با همان کلیدهای شناسهٔ وصله و Lab به‌علاوهٔ `captureId` می‌گیرد. گزارش ابزار `estimate` با `measurementId` و `measurementVersion` مثبت، و `reading` با Lab و شرایط یکسان `referenceWhite`، `observer`، `geometry`، `background` و `layers` لازم دارد. هندسه و زمینه باید غیرخالی و لایه عدد صحیح مثبت باشند. خوانش باید `instrumentId`، `source`، `method`، `measuredAt` با منطقهٔ زمانی و `physicalMeasurementConfirmed:true` واقعی داشته باشد. وضعیت آن `operatorSupplied` است، نه تأیید سخت‌افزاری توسط برنامه. مقادیر ساختگی آزمون هرگز به‌عنوان خوانش واقعی وارد نشوند.
